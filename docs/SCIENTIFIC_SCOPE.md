# 科学边界

open-tcm-discovery 用来检索和分析中药小分子。同一次分析里可以查公开数据库、看网络拓扑、算理化描述符、看对接姿势。每一步都留下数据来源。这里不出临床建议。计算排名不是药效。

写进报告之前，先把句子分成三句里的一句：这是某库在某时的记录，这是文献计量或试验登记，这是计算预测。对接那一句写成提议的对接模型。口袋残基必须能指回文献，不能写「对接发现了结合位点」。预测靶点单独成句，不要并进「已记录的靶点」或共识计数。

## 能做的计算

- 从疾病名检索通路和基因，再决定要不要做 PPI。
- 把一个成分或基因放到多个公开库里对照，保留每条记录的来源和时间。
- 用本地 SymMap 索引比较几味药的成分集合是否重叠。
- 在文献已经给出口袋残基时，跑 AutoDock Vina，并单独列出接触。
- 查找 PubMed 共现和 ClinicalTrials.gov 试验，作为下一步实验或阅读的索引。
- 对用户自备的机制表和分子库做加权评分，并用阳性药检查这套权重是否把已知药排在前面。

## 这些输出要怎么理解

| 输出 | 它是 | 它不是 |
|---|---|---|
| 多库共识分 | 若干数据库同时收录该实体 | 结合亲和力或临床有效 |
| OB/DL 过滤 | TCMSP 口径下的历史筛选门 | 与 HERB 等库的 DL 可互换的活性证明 |
| RDKit 描述符、ESOL、BBB/hERG 代理 | 分诊用近似 | 实测 ADMET |
| hub、敲除 z-score、图嵌入 | 网络拓扑 | 基因必需性或机制验证 |
| 文献共现 | 检索式命中篇数 | 因果关系 |
| 临床试验匹配 | 该病、该靶点或该成分附近有试验 | 中药候选的疗效 |
| Vina 亲和能与接触 | 提议的对接模型（proposed docking model） | 晶体结构、SPR 或已验证氢键 |
| 多臂综合分、`dock_rescore` | 优先级启发式 | 经过基准验证的打分函数 |
| 标识、基因符号、疾病名整理 | 格式检查，或本地对照表命中 | HGNC / MeSH 全库，也不是靶点已被收录 |
| 剂量换算和方内比例 | 按点名的那一套历史口径写成克 | 药效、暴露量或网络因果权重。也不是把所有「两」合成一个数 |
| TCMSP 旧站成分表，以及 OB/DL 开关 | 当次页面里的成分字段。开关只滤 `ob`、`dl` | 疗效，或其他库的类药性。这一页也不是靶点表 |
| TCMSP 成分名与 InChIKey 的本地对齐 | 调用方两张表上的字符串是否对得上 | 结构鉴定、PubChem 核对、靶点收录或疗效 |
| 调用方靶点表的 `recorded_source_count` | 这张表里，来源写明一个名称且标成 recorded 的不同来源数 | 在线多库共识、疗效，或把预测行算进去 |
| RDKit 规范 SMILES、InChIKey | 当前环境里 RDKit 写出的结构键 | 与 PubChem CanonicalSMILES 逐字相同的字符串 |

对接图上，预测残基带 `*`，接触用虚线。有突变、竞争或直接结合实验的残基才不带星号。措辞规范见 `references/evidence_grading.md`。

`tcm_convert_dose` 一次只接受一个 `convention`。不写口径会报错，不会替你选「两」。毫升和升不会换成克。`ratio_to_min` 是这次输入里相对最小剂量的重量比。`tcm_formula_weight` 在同一个口径下把各行克数相加。那里的重量比是该行占全方合计的比例，不是疗效，不是暴露量，也不是君臣佐使。炮制只保留原文。

| 口径名 | 这里的「两」 | 用在什么时候 |
|---|---|---|
| `metric` | 不接受「两」 | 只有 g、mg、μg、kg |
| `market_1959` | 50 g | 1959 年后市制。1 斤 = 10 两 = 500 g。这不是古方 |
| `han_tang` | 13.8 g | 汉唐。不接受「钱」和「厘」。一铢按 13.8/24 g |
| `song_yuan_2025` | 40 g | 2025 年网络药理学用表里的宋元行 |
| `ming_qing_2025` | 37 g | 同一张表里的明清行 |
| `song_jin_yuan_2024` | 41.3 g | 2024 年经典名方考证里的宋金元，按一钱 4.13 g |
| `ming_qing_2024` | 37.3 g | 同一篇考证里的明清，按一钱 3.73 g |

宋元和明清各有两套数字。点名的是哪一套，返回里的 `citation` 就写哪一套。不要把 `ming_qing_2025` 的 37 g 和 `ming_qing_2024` 的 37.3 g 折中。

`tcm_check_docking_replay` 不运行对接。通过只表示可以进入复现，结果仍是提议的对接模型。随附夹具不是已核对的公开复合物。方剂分析返回里，高重叠那一档的标签字面是「功效相近」。它按成分集合的重叠系数划分。写报告时改说集合重叠，不要顺着这个标签写成药效。文献共现是命中篇数。试验登记是 NCT 和分期。图嵌入是余弦相似度。敲除 z-score 是拓扑扰动。ADMET 面板是近似模型。这些句子都不能写成疗效。

## 统计与过滤约定

- 疾病–成分超几何检验的背景 N 取 20000，作为人蛋白编码基因数量的工作近似。多重比较用 Benjamini–Hochberg FDR。
- 成分进入「活性成分」讨论前，TCMSP 口径使用 OB≥30、DL≥0.18。这只用于 TCMSP 页面上的 `ob`、`dl`，并且只在 `ob_dl_filter` 打开时由 `tcm_tcmsp_search` 过滤。其他数据库的 DL 不混入这道门。RDKit 的 Lipinski 和 QED 另写。`tcm_align_tcmsp` 会抄出 `ob`、`dl`，并在两个数都有时填写 `tcmsp_ob_dl_pass`，但它不筛选，也不访问网站。名称相同不是结构相同。
- 深链对接默认 exhaustiveness 8、seed 42。批量筛选默认 exhaustiveness 4，只用于分诊；准备写入论文的姿势用 16 重跑。
- 同一种子重复对接，亲和能差超过 0.1 kcal/mol，记为复现红旗，先查受体准备是否确定，再解释生物学。
- D1 的 15 个基因、D5 的 −7 / −5 kcal/mol，是流程分支阈值。换阈值要在报告里写明。

## 可追溯性

在线工具成功返回时保留 `source` 和 `queried_at`。20 个只读工具有本地缓存，TTL 默认 3600 秒。命中缓存时仍显示原来的查询时间。错误响应不进缓存。缓存用 `tcm_cache_status` 清空。本地对齐没有 `queried_at`，因为它不是一次新的数据库请求。

`tcm_check_database_status` 在 `refresh` 为 false 时返回保存的探测表。表上的日期不是「这些库今天的结论」。正式分析前若要看现在通不通，再把 `refresh` 设为 true。九月的端点快照留在 `references/database_availability_2026-09.md`，不要拿它判断当前 TCMSP 该请求哪一个地址。

网络图用固定随机种子。Vina 会记下种子和 exhaustiveness。本地 DAG 把每条断言的文件或接口来源写进循证日志。

仓库里不放「某病的标准答案」。`data/herb_mol_index.json` 只是 SymMap 的药材–成分标识对照。

## 上游数据

用这些数据库时，遵守它们当时的使用条款。本仓库不转售，也不镜像完整库。代码里调用过、文档里记过可用性变化的来源有：SymMap、PubChem、ChEMBL、KEGG、STRING、Open Targets、Pharos、UniProt、Wikidata、DGIdb、CTD、GWAS Catalog、NCBI、g:Profiler、ClinicalTrials.gov、TCMBank、NPASS、HERB、TCMSP 旧站。

2026-09 的端点快照在 `references/database_availability_2026-09.md`。快照会过期。正式分析前用 `tcm_check_database_status` 再探一次。已经确认不能当数据通道用的，有 HPA 与 GTEx 的相关接口，以及 ADMETlab REST。GEO 只用来发现数据集，不下载表达矩阵。

## 软件引用

用了对接结果，请同时引用 AutoDock Vina 和它的版本。本流程按 1.2.5 的命令行接口编写。用了药材–成分索引，请引用 SymMap。本仓库的软件引用见根目录 `CITATION.cff`。
