## 阶段一：本地对齐 TCMSP 成分名和 InChIKey

**已经可以调用。** 有不访问网络的测试。工具名是 `tcm_align_tcmsp`。

`tcm_tcmsp_search` 给出的是旧站成分行。本地索引对不上这些英文名，也没有 InChIKey。本阶段不新开网站，只把调用方已经拿到的 TCMSP 行，和调用方自己的名称、InChIKey 表对在一起。跑完先看 `n_matches` 和 `n_ambiguous`。`ambiguous` 里的行不要挑一条当成对上了。`note` 会说明这不是一次新的网站请求。

输入：

- TCMSP 侧：`tcm_tcmsp_search` 的 JSON（读其中的 `ingredients`），或一张表。用得到的列是 `molecule_name`、`MOL_ID`、`ob`、`dl`。行里若已有 InChIKey，也读。
- 目录侧：调用方粘贴的表。需要成分名，或 `MOL_ID`，或 InChIKey，至少有一种。可以带一个调用方自己的 `local_id`。不读基因列。

输出：

- `link` 只取 `inchikey`、`inchikey_block`、`mol_id`、`name` 四种。同一行上多种键同时存在时，先看全键，再看不与 InChIKey 连接层冲突的 MOL_ID，再看连接层，最后才看名称。
- 两边都有合法 InChIKey 且 27 位全相同，记为 `inchikey`。这只说明字符串相同，没有向 PubChem 核对。
- 前 14 位相同、其余不同，记为 `inchikey_block`。不把它写成同一条立体化学记录。
- 两边 InChIKey 都有且前 14 位不同，不用名称硬并。
- 只有一侧有 InChIKey 时，名称对上了就记为 `name`，并把有键的那一侧抄过来，同时写明没有比对过结构。
- 同一键对上多行，或同一规范化名称对上多行，放进 `ambiguous`，不挑一行。
- `ob`、`dl` 原样抄出。`tcmsp_ob_dl_pass` 只在两个数都有时填写，表示是否达到 30 和 0.18。本工具不筛选，也不把这道门用到其他库。
- 没有 `queried_at`。这不是一次新的 TCMSP 请求。

验收：

- 单元测试不访问网络。名称相同不会编造 InChIKey。全键优先于不同的名称。连接层不同的两条键不会按名称并上。多行同名保持 ambiguous。
- 不内置同义词表，不读 `data/herb_mol_index.json`。
- 不进入 `tcm_smart_run` 的自动链，也不进只读检索缓存。
- 单侧最多 2000 行。这是调用方摘录，不是上游全库。

不做什么：

- 不访问 TCMSP 或其他网站，不把名称相同写成结构相同。
- 不读基因列，不把对齐结果写成靶点收录或疗效。
- 不改 OB≥30、DL≥0.18 的适用面。这道门仍然只解释 TCMSP 行上的 `ob`、`dl`。

## 阶段二：按行读入用户自备的靶点表

**本轮实现。已经可以调用。** 有不访问网络的测试。工具名是 `tcm_read_target_table`。

选这一段，是因为调用方手里的摘录可以在本地测完，而且后面的在线库都还没有一条能分出已记录和预测的可复现请求。BATMAN-TCM、ETCM、HERB、HIT、ITCM 的导出若要拿来用，由调用方按该库条款自己取得文件，再把摘录交给这个工具。这里不附带这些全库，也不替调用方判断某一行算不算已知相互作用。

输入：

- 一张本地表，或 JSON 的 `rows` / `targets` 列表。文本最长 100000 个字符，数据行最多 2000 行。
- 列名固定为 `compound_id`、`gene`、`support`、`source`。大小写不限，不另认中文列名或 `gene_symbol` 这类近义词。
- `support` 只认 `recorded` 和 `predicted`。大小写和首尾空白忽略。

输出：

- 每一行保留成分标识、基因符号、`support` 和来源，并带 `bucket`：`recorded`、`predicted` 或 `unclassified`。
- `recorded_pairs` 里的 `recorded_source_count` 只数同一成分、同一基因上，来源写明一个名称且 `support` 为 recorded 的不同来源。大小写不同的同一个来源只数一次。
- `predicted_pairs` 单独列出预测来源。这些来源不加入 `recorded_source_count`。
- 没有 `queried_at`。多出来的列只出现在 `ignored_columns` 里，单元格里的数不抄进结果。

验收：

- 单元测试不访问网络。夹具里同时有 recorded 和 predicted。预测来源不进 `recorded_source_count`。
- 空文本、只有表头、空的 JSON 列表都报错。
- 缺任一必填列就报错，不把缺的 `support` 当成 recorded。
- `known`、`experimental`、`预测` 这类写法，以及空来源、笼统词、一格里多个来源，放进 unclassified，不拆、不猜，也不进入已记录计数。
- 不进入 `tcm_smart_run` 的自动链，也不进只读检索缓存。

不做什么：

- 不内置靶点库，不去网站补行，不把这个计数写成 `tcm_cross_database_screen` 的在线共识。
- 不对照基因别名表，不把 `TNF` 和 `tnf` 并成一个符号。
- 不把 HERB 的类药性、RDKit 的 Lipinski 或 QED、表上多余的 `ob` / `dl` 读成 TCMSP 门槛。
- 不把预测行并进已记录证据，也不把这个计数写成疗效。

## 阶段五：方剂记录补上剂量和炮制字段

**已经可以调用。** 工具名是 `tcm_formula_weight`。它不进入 `tcm_smart_run` 的自动链。调用时把每一行剂量按点名的一个口径换成克，再给出全方合计，以及各行克数占合计的重量比。炮制按原文保留，没写就是空，不会填成生。这只是单条剂量换成克后的合计与炮制原文，不是君臣佐使。

`tcm_convert_dose` 仍然换单条剂量。七套口径不能并成一个「两」。`tcm_formula_analysis` 仍然只做成分集合的 Jaccard，不读剂量，也不读炮制。高重叠标签的字面是「功效相近」，读的时候仍是集合重叠。

输入：药材行，以及必填的口径。口径是 `metric`、`market_1959`、`han_tang`、`song_yuan_2025`、`ming_qing_2025`、`song_jin_yuan_2024`、`ming_qing_2024` 之一。每行要有药材名和剂量。炮制可以不写。缺口径、空方、混用公制和传统单位，或剂量无法解析，都会报错。

输出：每行克数、全方合计、各行重量比，以及炮制原文。返回里写明重量比不是疗效，不是暴露量，也不是君臣佐使。

## 阶段七：单细胞和多组学仍停在发现层

**数据集发现已经有了。表达矩阵和在线差异分析没有做。** `tcm_scrna_channel` 已经返回 GEO 的数据集编号、实验设计和相关文献。服务器不下载表达矩阵。返回里如果出现表达量或差异基因，那不是这个工具现在的行为。

调用方自己的表达谱若要和 HERB 的高通量实验比较，放进本地打分的可选输入，并在报告里写明样本和归一化方法。在线服务不做未经验证的差异分析。

输入：疾病或组织相关的检索词，沿用现在的 GEO 发现调用。比较表达时，只接受调用方自己准备好的本地表。

输出：数据集编号、实验设计和相关文献。没有表达矩阵，没有在线差异基因表。

验收：工具返回里没有表达矩阵。比较只在调用方提供本地表时发生，并保留方法说明。

不做什么：

- 不下载表达矩阵，不做未经验证的在线差异分析。
- 不把数据集发现写成机制或疗效。

## 明确不做

- 不猜测 BATMAN-TCM 的 JSON 参数，也不为 ETCM、HIT、ITCM 写没有夹具的空工具。HERB 详情只读已经跑通的 HTTP 页，不把那一页的靶点算成已记录证据。不给 TCMSP 新写靶点工具。
- TCMSP 的 OB≥30、DL≥0.18 只用于本库的 `ob`、`dl`。成分表不是靶点，也不是疗效。新平台介绍里的 15 和 0.11 不混进来。
- 不把预测靶点写成已知收录。`recorded_source_count` 只含调用方标明 `recorded`、且来源写明一个名称的行。
- 不做盲对接。不把文献共现、集合重叠、试验登记、剂量换算、方剂重量比、名称对齐、靶点表计数或对接复现门槛写成疗效。
- 名称对齐不是结构鉴定。InChIKey 全键相同只是调用方给出的字符串相同。
- 不把上游全库放进这里。阶段一、阶段二只接受有行数上限的摘录。
- 不改 `tcm_tcmsp_search` 的旧站地址、重试和空结果行为。
- 不改分析图的 300 个实体节点阈值、浅暖宣纸底和木色边框，也不改已有六个整理工具的含义。
- 不改统计函数、口袋规则和数据源路由的科学含义。
- 不在用户点名之前改写技能文件，也不把单次失败自动写成停用某个数据库。
- 阶段五只做单条剂量换成克后的合计和炮制原文，不写成君臣佐使。阶段六只做离线门槛，不写成已经复现了 3 到 5 个公开复合物。已核对的公开夹具仍是后续。
