# 技术路线

这份路线写于 2026-10-13。已完成的部分有离线测试。还没做成夹具的在线接口不写进工具。仓库面向任意 MCP 客户端，Cursor 只是接法示例。

核对时用过这些公开材料：BATMAN-TCM 2.0（Nucleic Acids Research, 2024, doi:10.1093/nar/gkad926）写了已知相互作用约 1.7 万条、高置信预测约 230 万条，并说网站有 API，参数是请求类型、输出格式和输入项；HERB 2.0（Nucleic Acids Research, 2025, 53(D1): D1404）；ETCM 2.0（http://www.tcmip.cn/ETCM2/front/）；TCMSP 介绍页 https://www.tcmsp-e.com/tcmsp.php 把旧版标成可以检索数据，靶点预测标成没有；HIT 2.0（http://hit2.badd-cao.net，Nucleic Acids Research, 2022）和 ITCM 下载页这次没有在本仓库里探测。2026-10-13 的 HTTP 结果仍以 [DATA_SOURCES.md](DATA_SOURCES.md) 为准。

## 已经完成

统一入口在本轮实现之后是 64 个工具：检索分析 27，对接建模 8，智能层 8，并行层 4，证据与出图 4，P1 有 3，P2 有 1，依赖自举 1，数据整理 6，TCMSP 旧站检索 1，成分名对齐 1。这些数字是 `mcp_server/` 里注册出来的。只跑 `open_tcm_discovery_mcp.py` 时列表会短一截，那不是工具被删了。下面各阶段里，写明「还没有」的都还不能调用。

- 在线结果带 `source` 和查询时间。仓库不预置疾病答案，也不放入上游全库。
- `tcm_tcmsp_search` 只读 `https://old.tcmsp-e.com/` 的药材表和成分表（`molecule_name`、`MOL_ID`、`ob`、`dl`）。超时 20 秒，超时或 HTTP 5xx 再试一次。失败时不补记录。
- OB≥30、DL≥0.18 只在 `ob_dl_filter` 打开时用于本页的 `ob`、`dl`。成分表不是靶点，也不是疗效。
- 实体节点少于 300 个时，分析图是浅暖宣纸底上的圆角卡片，木色边框。到 300 个按种类收成球壳。步骤节点不计入这 300。图例、检索通路、下一步建议和数据源状态是给智能体读的进度。文献共现、集合重叠和试验登记只标检索关系。
- `tcm_clean_table`、`tcm_normalize_ids`、`tcm_normalize_structure`、`tcm_normalize_genes`、`tcm_normalize_disease`、`tcm_convert_dose` 只整理调用方已经给出的文本。
- `tcm_formula_analysis` 用本地 SymMap 标识索引做集合重叠。`data/herb_mol_index.json` 只有药材和成分 ID，没有成分名，也没有 InChIKey。
- `tcm_align_tcmsp` 在一次本地调用里按优先级对齐：先全键，再不冲突的 MOL_ID，再 InChIKey 前 14 位，最后名称。不访问网站。名称相同不是结构相同。
- `tcm_self_iterate` 只在用户点名后追加 `references/runtime_lessons.md`。不改统计门槛、口袋规则和数据源路由。
- 超几何尾概率在抽中次数不可能发生时返回 0，不再把这种输入算成 1。疾病筛选脚本和 MCP 工具用的是同一段实现。
- 没有文献口袋就不对接。对接输出是提议的对接模型。同一种子再跑，亲和能差超过 0.1 kcal/mol，记为复现问题。
- 剂量换算已经按点名的口径分开。`metric`、`market_1959`、`han_tang`、`song_yuan_2025`、`ming_qing_2025`、`song_jin_yuan_2024`、`ming_qing_2024` 不能并成一个通用的「两」。按克加权方剂还没有做，见阶段五。

## 阶段一：本地对齐 TCMSP 成分名和 InChIKey

**已经可以调用。** 有不访问网络的测试。工具名是 `tcm_align_tcmsp`。

`tcm_tcmsp_search` 给出的是旧站成分行。本地索引对不上这些英文名，也没有 InChIKey。本阶段不新开网站，只把调用方已经拿到的 TCMSP 行，和调用方自己的名称、InChIKey 表对在一起。跑完先看 `n_matches` 和 `n_ambiguous`。`ambiguous` 里的行不要挑一条当成对上了。`note` 会说明这不是一次新的网站请求。

输入：

- TCMSP 侧：`tcm_tcmsp_search` 的 JSON（读其中的 `ingredients`），或一张表。用得到的列是 `molecule_name`、`MOL_ID`、`ob`、`dl`。行里若已有 InChIKey，也读。
- 目录侧：调用方粘贴的表。需要成分名，或 `MOL_ID`，或 InChIKey，至少有一种。可以带一个调用方自己的 `local_id`。不读基因列。

输出：

- `link` 只取 `inchikey`、`inchikey_block`、`mol_id`、`name` 四种。同一行上多种键同时存在时，先看全键，再看不与 InChIKey 连接层冲突的 MOL_ID，再看连接层，最后才看名称。
- 两边都有合法 InChIKey 且 27 位全相同，记为 `inchikey`。这只说明字符串相同，没有向 PubChem 核对。
- 前 14 位相同、其余不同，记为 `inchikey_block`。不把它写成同一条立体化学记录。
- 两边 InChIKey 都有且前 14 位不同，不用名称硬并。
- 只有一侧有 InChIKey 时，名称对上了就记为 `name`，并把有键的那一侧抄过来，同时写明没有比对过结构。
- 同一键对上多行，或同一规范化名称对上多行，放进 `ambiguous`，不挑一行。
- `ob`、`dl` 原样抄出。`tcmsp_ob_dl_pass` 只在两个数都有时填写，表示是否达到 30 和 0.18。本工具不筛选，也不把这道门用到其他库。
- 没有 `queried_at`。这不是一次新的 TCMSP 请求。

验收：

- 单元测试不访问网络。名称相同不会编造 InChIKey。全键优先于不同的名称。连接层不同的两条键不会按名称并上。多行同名保持 ambiguous。
- 不内置同义词表，不读 `data/herb_mol_index.json`。
- 不进入 `tcm_smart_run` 的自动链，也不进只读检索缓存。
- 单侧最多 2000 行。这是调用方摘录，不是上游全库。

## 阶段二：按行读入用户自备的靶点表

**还没有这个工具。** 下面是做的时候要遵守的约定，不是现在已经能调用的接口。现在没有 `support` 这一列，也不能把预测靶点算进已记录证据。本阶段打算做本地读入，仍不新接网站。HERB、ETCM、BATMAN-TCM、HIT、ITCM 或 TCMSP 导出若要拿来用，由调用方按该库条款自己取得文件，再把摘录交给工具。仓库不附带这些全库。

输入：一张本地表。每行至少有成分标识、基因符号，以及 `support`。`support` 只允许 `recorded` 或 `predicted`。缺了这一列就报错，不默认成已知收录。

输出：逐行原样保留标识和 `support`，并给出一个只统计 `recorded` 的计数。预测行可以列出，不进「几个库同时证实」。

验收：夹具里同时有 `recorded` 和 `predicted`。预测行不进共识计数。工具不访问网络。没有夹具里的列，就不设对应字段。

## 阶段三：BATMAN-TCM 2.0 只做探针

**还没有夹具，也没有工具。** 论文写了 API，但没有在论文正文里给出可粘贴的参数表。2026-10-13 探测：首页 20 秒超时，`index.php` 连接被关掉，HTTPS 握手失败。这次没有可复现的 JSON。在站点能打开并留下夹具之前，调用方不能从本仓库得到 BATMAN 的靶点行。

输入：等站点能打开之后，保存一条请求（类型、格式、输入项）和一条已知相互作用的响应，放进 `tests/fixtures/` 或 `references/`。

输出：先是这份夹具和字段说明。工具要等夹具能分出 `recorded` 和 `predicted` 再写。分不出来就不做工具。

验收：不猜测 URL 查询参数。预测靶点不写成已知收录。

## 阶段四：ETCM、HERB，以及这次没探测的库

**还没有收成工具。** 2026-10-13 已经看到、但没有收成夹具的响应：

- ETCM：`/ETCM/api/` 仍是 404。`http://www.tcmip.cn:18124/home/detail/` 对黄连返回了 JSON，药名 HuangLian。`POST /home/herb_chem_phy/` 返回成分名和分子量，不是 OB、DL。
- HERB：`http://herb.ac.cn/v2` 没有连上。`POST http://47.92.70.12/chedi/api/` 的 `detail_api` 对 `HERB000281` 返回了 JSON 正文，`Content-Type` 却是 `text/html`，其中有 `herb_ingredient`。类药性不能代替 0.18。

这些字段还不能当测试夹具复现，所以本轮不做 ETCM 或 HERB 工具。下一步是各存一条原始响应，写明字段，再决定要不要做只读解析。分子量、成分名列表和 `herb_ingredient` 都不是 TCMSP 的 `ob`、`dl`，也不是靶点收录，除非响应里另有写明的字段。

HIT 2.0 和 ITCM 的下载页这次没有探测。SymMap 的成分描述文件（SMIT）含名称，本仓库的索引没有这份描述。三者都先留在本阶段：要嘛以后做一次带记录的探测，要嘛调用方把摘录交到阶段二。TCMSP 介绍页把旧版的靶点预测标成没有；成分夹具里也没有靶点列。`www.tcmsp-e.com/tcmspsearch.php` 在 2026-10-13 是入口页，不是旧表格。不另写靶点抓取。介绍页文字里，新平台示例用了另一组阈值（OB≥15%、DL≥0.11）。那不是本仓库的门。`next.tcmsp-e.com` 这次没有可复现的查询参数，不接。

验收：没有夹具就不注册工具。有夹具之后，解析测试不访问网络。

## 阶段五：方剂记录补上剂量和炮制字段

**换算工具已经有了，按克加权还没有。** `tcm_convert_dose` 已经按点名的度量衡把剂量换成克，并给出本次输入的重量比。七套口径不能并成一个「两」。`tcm_formula_analysis` 仍然只做成分集合的 Jaccard，不读剂量，也不读炮制。高重叠标签的字面是「功效相近」，现在读它的时候仍是集合重叠。

输入：调用方在药对或复方记录里可选地给出剂量和炮制品。没有这些字段时，行为与现在相同。

输出：没有字段时写明「这是集合运算」。有剂量时可以按克重加权。加权结果仍然不是药效，也不是暴露量。

验收：缺字段的旧调用结果不变。有字段的夹具能复算重量比。测试不访问网络。

## 阶段六：一小套公开复合物的对接复现

**还没有这套夹具，也还不能拿来当回归。** 计划是选 3 到 5 个公开复合物。口袋来自文献或晶体配体。用固定的 exhaustiveness 和种子跑 Vina，把亲和能差和接触残基写进夹具。同一种子再跑，亲和能差超过 0.1 kcal/mol，仍记为复现问题。在夹具写好之前，单次对接结果仍然只是提议的对接模型。

没有晶体配体、也没有文献残基的靶点，继续停在对接之前。不做全蛋白盲对接。不把 AlphaFold 复合物模型写成实验结构。

验收：夹具里的口袋残基能追溯到文献或 PDB 配体。没有口袋的条目不会跑出姿势。

## 阶段七：单细胞和多组学仍停在发现层

**数据集发现已经有了。表达矩阵和在线差异分析没有做。** `tcm_scrna_channel` 已经返回 GEO 的数据集编号、实验设计和相关文献。服务器不下载表达矩阵。返回里如果出现表达量或差异基因，那不是这个工具现在的行为。

调用方自己的表达谱若要和 HERB 的高通量实验比较，放进本地打分的可选输入，并在报告里写明样本和归一化方法。在线服务不做未经验证的差异分析。

验收：工具返回里没有表达矩阵。比较只在调用方提供本地表时发生，并保留方法说明。

## 明确不做

- 不猜测 BATMAN-TCM 的 JSON 参数，也不为 ETCM、HERB 写没有夹具的空工具。
- TCMSP 的 OB≥30、DL≥0.18 只用于本库的 `ob`、`dl`。成分表不是靶点，也不是疗效。新平台介绍里的 15 和 0.11 不混进来。
- 不把预测靶点写成已知收录。共识计数只含调用方标明 `recorded` 的行。
- 不做盲对接。不把文献共现、集合重叠、试验登记、剂量换算或名称对齐写成疗效。
- 名称对齐不是结构鉴定。InChIKey 全键相同只是调用方给出的字符串相同。
- 不把上游全库放进仓库。阶段一、阶段二只接受有行数上限的摘录。
- 不改 `tcm_tcmsp_search` 的旧站地址、重试和空结果行为。
- 不改分析图的 300 个实体节点阈值，也不改已有六个整理工具的含义。
- 不在用户点名之前改写技能文件，也不把单次失败自动写成停用某个数据库。
